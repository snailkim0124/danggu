# 플레이 게이트 체크리스트

실제 4구 당구대에서 앱의 추천 샷이 정말로 맞는지 확인하는 테스트입니다. **이 게이트는 사람이 직접 당구를 쳐야 합니다** — Claude가 대신할 수 없는 유일한 검증 단계입니다.

- 참고 문서: `.omc/plans/danggu-4gu-path-guide-plan.md` (Phase 5 — 검증)
- 결과 기록: 이 체크리스트대로 진행하면서 [`play-gate-results-template.md`](./play-gate-results-template.md) (또는 `.csv`)에 바로바로 적으세요.
- 완료 후: 채워진 결과표를 Claude에게 전달하면 70% 기준 통과 여부와 실패 패턴을 집계해 드립니다.

## 1. 준비물

- 4구 당구대 1대 (대대 또는 중대 — 앱 설정에 등록한 규격과 동일해야 함)
- 큐스틱, 흰공 1개·노랑공 1개·빨간공 2개
- 사진 촬영용 스마트폰 (앱 접속용과 동일해도 무방)
- 이 체크리스트 + 결과 기록용 템플릿 (인쇄하거나 옆에 띄워두기)

## 2. 시작 전 확인 사항

- [ ] 앱 설정(Settings)에서 **큐볼 색상**(흰공/노랑공)이 본인이 실제로 사용할 색상과 일치하는지 확인
- [ ] 앱 설정에서 **테이블 규격**(대대/중대)이 지금 사용할 테이블과 일치하는지 확인
- [ ] 아래 "10건 배치 사양" 표를 한 번 훑어보고, 좌표 표기법(§3)을 이해했는지 확인

## 3. 좌표 표기법 (배치를 재현 가능하게 세팅하기 위한 규칙)

모든 배치는 **테이블을 위에서 내려다본 기준**, 쿠션 안쪽(공이 굴러다니는 선) 기준 **비율 좌표**로 표기합니다.

- `x = 0` : 왼쪽 단쿠션(짧은 변), `x = 1` : 오른쪽 단쿠션
- `y = 0` : 촬영자와 가까운 쪽 장쿠션(긴 변), `y = 1` : 반대쪽 장쿠션
- 예: `(0.25, 0.30)` = 왼쪽 단쿠션에서 테이블 가로길이의 25% 지점, 촬영자 쪽 장쿠션에서 테이블 세로길이의 30% 지점

```
y=1  ┌───────────────────────────────┐
     │                                │
     │          (0.5, 0.5) ← 중앙      │
     │                                │
y=0  └───────────────────────────────┘
    x=0                              x=1
```

줄자로 테이블 가로/세로 길이를 한 번 재두면, 이후 모든 배치는 그 길이의 비율로 환산해 놓으면 됩니다 (예: 중대 가로 2438mm × 25% ≈ 610mm 지점).

> **주의**: 아래 좌표는 각 기술 유형(직접샷/1쿠션/막힘)이 물리적으로 성립하도록 설계한 **참고 배치**이며, 당구 시뮬레이션으로 검증된 완벽한 정답 각도는 아닙니다. 실제로 어떤 샷이 나오는지, 그리고 앱이 추천한 대로 쳤을 때 맞는지를 확인하는 것이 이 테스트의 목적입니다. 좌표를 ±0.05 정도 조정해도 괜찮지만, **한 번 정했으면 10건 모두 다시 테스트할 때도 같은 좌표를 사용**해야 결과를 비교할 수 있습니다.

## 5. 배치별 진행 순서 (10건 각각 동일하게 반복)

1. **배치**: 위 표의 좌표에 맞춰 공 4개를 놓습니다.
2. **베이스라인 결정**: 사진을 찍기 전에, 본인이라면 이 배치에서 어떻게 칠지(어느 공을 어떤 두께/각도로) 먼저 마음속으로 정하고 메모해 둡니다. **앱의 추천을 먼저 보면 안 됩니다** — 순서가 바뀌면 비교가 무의미해집니다.
3. **촬영/업로드**: 배치를 건드리지 않은 상태 그대로 사진을 찍어 앱에 업로드합니다. **테이블 위쪽에서 아래로 내려다보는 구도(가파른 각도)는 피하세요** — 당구를 실제로 칠 때처럼 테이블 옆/짧은 변 쪽에 서서 눈높이~가슴 높이로 비스듬히 찍어주세요. 자세한 이유는 `geometric-gate-guide.md` §2의 촬영 각도 제한 참고 — 가파른 각도에서는 인식 오차가 크게 늘어난다는 게 실사진 30장으로 확인됐습니다.
4. **인식 확인**: 앱이 인식 확인 화면을 보여주면, *공 색상이 뒤바뀌었거나 개수가 틀리는 등 명백히 잘못된 경우만* 보정하세요. 미세한 위치 오차는 보정하지 말고 그대로 진행합니다 (이 게이트는 전체 파이프라인의 실전 성공률을 보는 것이 목적입니다).
5. **추천 기록**: 앱이 보여주는 대표 추천 샷의 기술 종류·조준 두께·각도·힘 단계를 결과표에 적습니다.
6. **베이스라인 시도**: 공을 1번 배치로 정확히 되돌린 뒤, 2번에서 정한 본인의 샷을 **1회** 시도하고 적중 여부를 기록합니다.
   > **베이스라인은 참고용이지 합격 기준이 아닙니다.** §7의 70% 통과 기준은 오직 "추천 샷" 결과로만 계산되고, 베이스라인은 거기에 전혀 반영되지 않습니다. 순전히 스트로크 실수(당점/힘 조절 실패, 미스큐 등)로 베이스라인을 못 맞혀도 신경 쓰지 말고 그냥 실패(X)로 기록하면 됩니다 — 왜 못 맞혔는지(내 판단 자체가 무리한 샷이었는지 vs 단순 실행 실수였는지) 한 줄 정도만 비고에 적어두면, 나중에 "앱 추천이 내 판단보다 나았는지" 비교할 때 더 정확하게 해석할 수 있습니다.
7. **추천 샷 시도**: 공을 다시 1번 배치로 되돌린 뒤, 앱이 추천한 샷을 그대로 **3회** 시도합니다 (매 시도 전마다 공을 원위치로 되돌리세요). 각 시도의 적중 여부를 기록합니다. 3회 중 실행 실수로 놓친 시도가 있다면 이 역시 비고에 남겨두세요 — 앱의 계산 자체가 틀렸는지, 아니면 실행이 어려워서였는지 구분하는 데 씁니다 (3회를 허용하는 것 자체가 스트로크 편차를 어느 정도 흡수하기 위한 설계입니다).
8. 다음 배치로 넘어가 1~7을 반복합니다.

## 6. "적중" 판정 기준 (D2 기준 — 반드시 이 기준으로만 판정)

**적중** = 큐볼이 빨간공(적구) **2개 모두**에 접촉했고, 상대공(상대방 색 공)에는 **전혀 접촉하지 않은** 경우만 인정합니다.

- 적구 1개만 맞혔다 → **실패**
- 적구 2개를 다 맞혔더라도 도중에 상대공을 건드렸다(파울) → **실패**
- 순서·경로가 앱이 보여준 다이어그램과 조금 달라도, 위 조건만 만족하면 **적중**으로 인정 (실전에서는 정확히 같은 경로로 안 굴러갈 수 있으므로 최종 결과만 판정 기준)

## 7. 다 끝난 후

10건 × (베이스라인 1회 + 추천 샷 3회) 기록을 모두 채운 결과표를 Claude에게 전달하세요. 추천 샷 적중률(목표: 70%, 즉 10건 중 7건 이상에서 3회 중 최소 1회 이상 적중 — 정확한 집계 규칙은 결과 전달 시 함께 확인)과 베이스라인 대비 비교, 실패 패턴(어떤 기술 종류에서 주로 실패하는지)을 분석해 드립니다.
