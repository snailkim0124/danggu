## 0. 프로젝트명

4구(사구) 당구 샷 경로 자동 안내 서비스

## 1. why - 목적

- 사용자가 4구 당구대 위 공 배치 사진 한 장만으로, 어디를 어떻게 쳐야 할지 알기 어려운 문제를 해결
- 실전에서 바로 따라칠 수 있는 수준(각도·힘 수치)의 캐롬 경로를 자동으로 계산해 제시함으로써 실력과 무관하게 최적의 샷을 선택할 수 있도록 지원

## 2. who - 타깃 사용자

- 4구 당구를 즐기지만 캐롬 경로(특히 뱅킹/고급 기술샷) 계산에 어려움을 겪는 사용자
- 매 타석마다 사진 한 장으로 빠르게 샷 가이드를 받고 싶은 모바일 웹 사용자

## 3. User Flow

1. **사전 설정:** 사용자가 자신의 큐볼 색상(흰공/노랑공)을 설정에서 미리 지정
2. **촬영/업로드:** 모바일 브라우저에서 당구대 사진 1장을 촬영 또는 업로드
3. **자동 인식:** 시스템이 테이블 경계와 공 4개(흰공1·노랑공1·빨간공2) 위치를 완전 자동으로 인식
   - 인식이 불확실한 경우, 사용자가 터치로 공 위치를 수동 보정 (fallback)
4. **경로 계산:** 시스템이 직접샷부터 1쿠션·2쿠션 이상·뱅크샷까지 모든 가능한 캐롬 경로를 계산 (회전/끌어치기/밀어치기는 기술 종류가 아니라 모든 경로에 독립적으로 적용되는 속성 — §9 갱신 이력 참고)
5. **대표 샷 제시:** 기술 종류 우선순위(직접 < 1쿠션 < 2쿠션 이상 < 뱅크샷) 기준 가장 쉬운 샷을 대표로, 각도·힘 수치와 함께 정적 2D 다이어그램으로 표시. 사용자가 설문으로 입력한 자기 실력 프로필이 이 우선순위를 개인화한다
6. **후보 탐색:** 사용자가 난이도 순 상위 3개 샷 후보를 탭/스와이프로 전환하며 확인

## 4. 기능 요구 사항

### P0 - 핵심 기능

- **사진 촬영/업로드(Capture):** 모바일 브라우저에서 단일 정지 사진 1장 업로드 (실시간 영상/AR 라이브 뷰 아님)
- **테이블·공 자동 인식(Vision Recognition):**
  - 사람 시점(비스듬한 각도) 사진 지원, 원근보정(캘리브레이션) 필수
  - 테이블 경계 및 공 4개(흰공/노랑공/빨간공×2) 위치를 완전 자동(AI)으로 인식
  - 인식 불확실/실패 시 사용자 터치 기반 수동 보정 fallback 제공
- **큐볼 설정 저장:** 사용자의 큐볼 색상(흰공/노랑공)을 설정에 미리 지정해 재사용 (매번 묻지 않음)
- **캐롬 경로 계산(Path Calculation):**
  - 직접샷, 1쿠션, 2쿠션 이상, 뱅크샷(쿠션을 먼저 맞히는 빈쿠션치기)을 포함한 모든 가능한 경로 계산 — 분류 기준은 순전히 큐볼 경로의 쿠션 접촉 횟수/순서이며, 회전(끌어치기/밀어치기/좌우 회전)은 기술 종류가 아니라 모든 경로에 독립적으로 적용 가능한 속성이다
  - 기술 종류 우선순위(직접 < 1쿠션 < 2쿠션 이상 < 뱅크샷) 기준 최적(가장 쉬운) 샷을 대표로 선정 — 뱅크샷은 조준 기준점(다른 공)이 없어 숙련도와 무관하게 가장 어려운 것으로 취급해 항상 최하위
  - 사용자가 설문으로 입력한 자기 실력 프로필(끌어치기/밀어치기/얇게치기/회전/뱅크샷/3쿠션 이상)이 위 기본 우선순위를 개인화한다 (§P1 참고 — 최초 계획과 달리 v1에 포함됨)
  - **키스(의도치 않은 다른 공과의 충돌) 회피:** 맞은 공이 튕겨나가는 방향이 다른 공과 가까울수록 해당 후보의 confidence를 연속적으로 감점 (하드 필터 아님)
  - 실전에서 바로 따라칠 수 있는 수준의 각도(도)·힘(강도) 수치 산출
  - 유효한 캐롬 경로가 하나도 없는 경우, 가장 근접한(거의 성공할 법한) 샷을 참고용으로 제시
- **결과 시각화(Result Visualization):**
  - 원본 사진 오버레이가 아닌 재구성된 정적 2D 다이어그램으로 표시
  - 난이도 순 상위 3개까지 샷 후보를 탭/스와이프로 전환 가능

### P1 - 추가 기능 (v1에 포함됨 — 최초 계획에서 변경)

- **개인화 난이도 프로필(User Skill Profile):** 사용자 설문(끌어치기/밀어치기/얇게치기/회전/뱅크샷/3쿠션 이상, 1~5점) 기반 개인 난이도 기준 적용. 최초 PRD는 이를 v2 이후로 보류했으나, 실사용 피드백에 따라 v1에 포함되어 이미 구현·배포됨

## 5. Non-Goals (범위 제외)

- 실시간 카메라/AR 라이브 오버레이
- 점수 기록, 경기 이력 관리, 멀티플레이어 대전 모드
- 100% 오차 없는 인식 보장 (수동 보정 fallback으로 대응, 완전 무결점 목표 아님)

## 6. Acceptance Criteria

- [x] 사용자가 모바일 브라우저에서 당구대 사진 1장을 업로드하면, 시스템이 테이블 경계와 공 4개(흰공/노랑공/빨간공×2) 위치를 자동으로 인식한다 — 쿠션 노즈선 자동보정(v0.4.0), 붙어있는 공 분리(v0.5.0/0.5.1)까지 반영해 실제 사진 기준으로 검증됨(`lib/vision/realPhotos.test.ts`). 지오메트릭 게이트는 합성 사진만 통과했고 계획이 요구하는 실제 사진 N≥30장 검증은 아직 없음(`PLAN.md` Phase 5 참고)
- [x] 인식이 불확실한 경우 사용자가 터치로 공 위치를 수동 보정할 수 있다 — 2D 평면 드래그(v0.2.0) + 사진 위 쿠션 모서리 드래그(v0.4.0)로 구현. 인식 자체가 근사치(fallback placeholder)일 땐 오해를 막기 위해 사진 위 오버레이를 아예 숨김(v0.4.1)
- [x] 시스템은 설정에 저장된 사용자의 큐볼 색상(흰공/노랑공)을 기준으로 경로를 계산한다
- [x] 시스템은 직접샷, 1쿠션, 2쿠션 이상, 뱅크샷을 포함한 모든 가능한 캐롬 경로를 계산하고, 기술 종류 우선순위(직접 < 1쿠션 < 2쿠션 이상 < 뱅크샷) 기준으로 가장 쉬운 샷을 대표로 제시한다 (회전은 기술 종류가 아닌 독립 속성으로 반영 — §9 갱신 이력 참고)
- [x] 추천된 샷은 각도(도)와 힘(강도) 수치를 포함해 실전에서 바로 따라칠 수 있는 수준으로 제공된다
- [x] 결과는 사진이 아닌 정적 2D 다이어그램으로 재구성되어 표시되며, 사용자는 여러 샷 후보를 탭/스와이프로 전환해 볼 수 있다
- [x] 점수 기록, 경기 이력, 멀티플레이어 기능은 이번 버전에 포함되지 않는다

## 8. 참고 — 기술 스택 방향 (미확정, 그린필드)

- **프론트엔드:** 웹, 모바일 브라우저 카메라/파일 업로드 (`getUserMedia` 또는 `<input type="file" capture>`)
- **비전 인식:** 테이블 경계 검출(세그멘테이션/코너 검출) + 공 검출(색상/원형 검출 또는 객체 탐지 모델) + 원근 변환(호모그래피)로 실측 좌표 환산
- **경로 계산:** 2D 당구 물리 엔진(쿠션 반사각 계산 포함), 기술종류별 후보 열거 + 난이도(기술위계) 기준 랭킹
- **백엔드/설정 저장:** 큐볼 색상 프리셋 저장을 위한 경량 저장소(로컬 스토리지 또는 간단한 서버 설정)

## 9. 문서 이력 및 참조

- 본 PRD는 Deep Interview(18라운드, 최종 앰비규어티 14%)의 결과인 `deep-interview-danggu-4gu-path-guide.md`를 기반으로 재구성됨
- **2026-08-30 갱신 (실사용 피드백 반영, 코드와 문서 재동기화):**
  - **고급 기술샷(스핀) 기술 계층 폐지.** 사용자 피드백: "고급 기술샷(스핀)은 없애고 1쿠션 또는 2쿠션 이상이라고 표시해줘 — 1쿠션은 수구 가는 경로에 쿠션을 1번, 2쿠션 이상은 2번 이상 맞는 것." `technique`은 이제 순전히 큐볼 경로의 쿠션 접촉 횟수(0/1/2+)와 접촉 순서(공보다 쿠션이 먼저면 뱅크샷)로만 정해지고, 회전(끌어치기/밀어치기/좌우 회전)은 `tipOffset`이라는 기술과 무관한 독립 속성이 됨. 뱅크샷은 "누구나 치기 어려운 샷"이라는 피드백에 따라 우선순위 최하위로 고정
  - **개인화 난이도 설문을 v1에 포함.** 최초 PRD/Non-Goals는 이를 v2 이후로 명시했으나, "설문조사 기능이 없어서 추가해야함"이라는 피드백에 따라 v1에서 이미 구현·배포됨(끌어치기/밀어치기/얇게치기/회전/뱅크샷/3쿠션 이상 6개 항목, 1~5점)
  - **키스(의도치 않은 다른 공과의 충돌) 회피 추가.** 최초 PRD/PLAN에 없던 신규 항목. 맞은 공이 튕겨나가는 방향이 다른 공에 가까울수록 해당 후보의 confidence를 연속적으로 감점(하드 필터 아님)
  - **`PLAN.md`의 `recognitionStatus`/`missMargin` 필드가 실제로는 각각 `confidence`+`needsManualCorrection`(boolean), `SimulationResult.missDistanceMm`으로 구현됨** — 상세 근거는 `PLAN.md`의 "변경 이력 (v2 → v3)" 및 Architecture/Data Model 섹션 참고
  - Acceptance Criteria 체크박스를 실제 구현 상태 기준으로 갱신 (MVP 완성 판정 제외 전부 충족)
- 의사결정 근거, 라운드별 질의응답 전문, 앰비규어티 추이는 원본 `deep-interview-danggu-4gu-path-guide.md`(인터뷰 기록)를 참조
